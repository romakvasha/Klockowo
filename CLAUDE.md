# Klockowo — сайт-гра з математики польською для дитини 5–6 років

## Що це
- Особистий сайт (не для магазинів застосунків): дитина вчиться рахувати до 100 і додавати.
- Інтерфейс і озвучка — **польською**. Зі мною (власником, батьком дитини) спілкуйся **українською**.
- Стиль: блоковий світ + власна команда цуценят-рятувальників (провідник — бігль Kubik). Жодних персонажів, логотипів чи впізнаваних елементів Minecraft або «Psi Patrol».

## Джерела (пріоритет згори вниз)
1. `docs/BRIEF.md` — поведінка, екрани, ігри, правила. Польські рядки звідси вставляй **дослівно**.
2. `design/` (експорт із Claude Design) і його зміст `design/INDEX.md` — вигляд: токени, компоненти, SVG. Розбіжність у вигляді → перемагає дизайн; у поведінці й текстах → бриф. Якщо не ясно — спитай мене.
3. `docs/PEDAGOGY.md` — методика: рівні, складність, підказки, адаптивність (застарілі назви позначені на початку файлу).
4. `docs/POLISH_COPY.md` — граматика й додаткові польські тексти.

Не читай ці файли повністю без потреби — лише розділи, названі в поточному етапі `docs/PLAN.md`. Замість сканування `design/` читай `design/INDEX.md`.

## Стек (не змінюй без моєї згоди)
- Vite + React + TypeScript (strict). Стан — zustand (persist у localStorage, з версією схеми й міграціями). Маршрути — react-router з HashRouter.
- Стилі — CSS Modules + CSS custom properties; токени з дизайну — у `src/styles/tokens.css`. Шрифти локально через @fontsource (Fredoka, Nunito, Andika; обов'язково latin-ext).
- Анімації — CSS і Web Animations API; бібліотеку `motion` додавай лише якщо без неї ніяк. Перетягування — власний хук на Pointer Events (миша + дотик), завжди з альтернативою «дотик по предмету → дотик по місцю».
- Голос — Web Speech API (pl-PL) лише через `src/speech/tts.ts`: черга, `speak()` повертає Promise після завершення, вибір голосу, швидкість, гучність, заміна окремих фраз на mp3 з `public/audio/`, якщо файл є. Звукові ефекти й тиха фонова музика (повзунок «Muzyka») — синтез через Web Audio API (без аудіофайлів).
- Тести — Vitest для чистої логіки (граматика, генератори завдань, перевірка відповідей, адаптивність, прогрес). E2E-тестів не пишемо.
- Без бекенду, аналітики, реклами, зовнішніх посилань і запитів.

## Структура `src/`
```
app/          App, маршрути, провайдери
screens/      один файл або папка на екран із BRIEF §6
components/ui/    PlayButton, IconButton, AnswerTile, DigitCard, CheckButton, HUD, ProgressBones, ...
components/math/  CountableObject, DropZone, TenFrame, BeadRack20, DotCard, NumberLine, JumpArc, HundredChart, BlockCube, BlockRod, BlockPlate, StickBundle, PlaceValueMat
characters/   Kubik, TeamPup, PlayerPup, MascotStage
games/        engine/ (цикл завдання, підказки, черга повторів) + по папці на міні-гру: generate.ts, check.ts, View.tsx
curriculum/   worlds.ts, levels/ (дані рівнів: список TaskSpec), adaptivity.ts, review.ts
speech/       tts.ts, sfx.ts, music.ts, lines.ts (УСІ польські рядки), plural.ts, numberWords.ts, nouns.ts
store/        profiles, settings, progress (zustand)
styles/       tokens.css, global.css
assets/       SVG із дизайну (окремими файлами)
dev/          сторінки-вітрини /#/dev/... для перевірки компонентів
```
Назви компонентів — як у BRIEF §8, щоб збігалися з дизайном.

## Польська мова в коді
- Узгодження числівника й іменника — лише через `Intl.PluralRules('pl')` (one/few/many) і словник `nouns.ts` з формами {one, acc1, few, many} і родом (jeden/jedna/jedno, dwa/dwie). Правила — `docs/POLISH_COPY.md` §8.
- Числа в репліки голосу йдуть **словами** (`numberWords.ts`, 0–100, покрито тестами), не цифрами.
- Жодних форм минулого часу чи -ł/-ła щодо дитини.
- Усі польські рядки — в `src/speech/lines.ts`, не розкидай їх по компонентах.

## Правила роботи (важливо через ліміт використання)
1. **Одна сесія = один етап** із `docs/PLAN.md` (перший невідмічений). Наступний етап не починай, поки я не попрошу.
2. На початку: прочитай `docs/PLAN.md` (разом із «Журналом»), виконай `git status` і `git log --oneline -5`. Якщо попередній етап не завершено (є `wip`-коміт або незакомічені зміни) — спершу заверши його.
3. Читай лише потрібне: `design/INDEX.md`, названі в етапі розділи BRIEF, конкретні файли коду. Не перечитуй великі файли без причини.
4. Не запускай субагентів, workflow чи багатоагентні режими, якщо я прямо не попрошу.
5. Файли тримай короткими (до ~300 рядків). Великі SVG — окремими файлами в `src/assets/`.
6. Кожен екран одразу верстай адаптивно за BRIEF §12 (етап M23 — лише шліфування).
7. Якщо етап виявився завеликим — зроби частину, а решту допиши в `docs/PLAN.md` як новий етап (напр., M9b).
8. Перед завершенням: `npm run build` і `npm test` проходять → коміт англійською (`feat(M8): game engine and "Policz i dotknij"`) → у `docs/PLAN.md` відміть етап `[x]` і додай у «Журнал» 3–5 рядків: що зроблено, що перевірити, відомі проблеми.
9. Наприкінці скажи мені українською: що відкрити й перевірити (`npm run dev`, адреса; для телефона — `npm run dev -- --host`) і що вставити в наступну сесію. Потім зупинись.
10. Якщо з'явилося попередження про ліміт — одразу закоміть поточний стан як `wip(Mx): ...` і запиши в «Журнал», на чому зупинився.

## Якість для дитини (перевіряй у кожному етапі)
- Цілі дотику ≥ 64 px (на телефоні ≥ 80), нічого не залежить від hover.
- Жодних таймерів, червоних хрестиків, штрафів; сигнал ніколи не лише кольором.
- Поважати `prefers-reduced-motion` і налаштування «Mniej animacji».
- Звук, музика і голос — лише після першого дотику («Graj!»); музика тиха й завжди стихає під голосом.
- Наступне завдання — лише коли голос договорив.
